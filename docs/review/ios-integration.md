# iOS·서버 연동 협의표

[개발 참고용 협의표 원본](../api/ios-integration.md) · [문서 안내](../README.md)

> **팀 검토용 초안** — 서비스 방향과 API 제안을 논의하기 위한 자료입니다. 전체 명세를 일괄 적용하자는 의미가 아니며, 미합의 항목은 협의 후 확정합니다. 이 폴더의 두 문서만 공유해도 읽을 수 있도록 구성했습니다.

[API 명세 첫 화면](api-spec.md) · [운동 업로드 예시](api-spec.md#examples)

**v0.4 · 2026-11-02 · 회의용**

이 표는 합의된 요구사항과 구현 협의가 필요한 내용을 구분한다. 기존 iOS 코드는 `33f55613ce17a91ce9656b780e92e84960540578` 커밋을 읽어 확인한 범위다. 현재 브랜치가 이미 변경됐다고 단정하지 않으며 아래 권장안은 승인된 구현 변경이 아니다.

## 1. 이미 정해진 내용

| 항목 | 기준 |
| --- | --- |
| 기록 대상 | 각자 본인 경기만 기록 |
| 저장 단위 | 쿼터별 골·어시스트 합계, 대표 포지션 하나, 운동 원본 |
| 원본 보존 | GPS와 심박 수집값 전체를 서버에 저장 |
| 결과 조회 | 서버가 계산해 저장한 요약을 조회 |
| TRIMP | Edwards 한 방식 |
| 서비스 시간대 | Asia/Seoul. 일반 날짜는 +09:00 포함 문자열 |
| 운동 원본 날짜 | 기존 Apple epoch 숫자 형식 유지. DB 내부는 UTC |

## 2. 먼저 결정할 연동 항목

| 우선순위 | 협의 항목 | 현재 명세·확인한 iOS 상태 | 결정할 내용 / 권장 방향 |
| --- | --- | --- | --- |
| 1 | 쿼터 식별 | 서버는 URL에 quarterId 필수. WorkoutPayload에는 서버 쿼터 ID 없음 | 측정 전에 서버 quarterId를 워치로 전달할지, 로컬 UUID를 서버 ID와 매핑할지. 지연 수신 파일을 현재 화면의 쿼터로 추정하지 않기 |
| 1 | 개인 기록 전달 | 워치에 골·어시스트·포지션이 있지만 운동 전송 본문에는 없음 | 전송 데이터/메타데이터에 함께 포함하고 iPhone이 GAME-14/GAME-10으로 저장하는 방식 합의 |
| 1 | 오프라인 시작 | 현재 서버 계약은 서버에서 만든 경기·쿼터 ID를 요구 | 확정(#44): 연결이 없으면 새 경기·쿼터 시작을 막는다. 이미 시작된 쿼터의 센서 파일은 ID 매핑을 보관해 재연결 후 업로드 |
| 1 | 공통 HTTP 클라이언트 | 기존 iOS는 이전 사용자별 업로드 경로와 최상위 DTO 응답 사용 | 새 쿼터별 경로, {data,meta}, {error,meta}, Bearer 인증, 헤더·상태 코드를 함께 적용하는 일정 |
| 1 | 날짜 인코딩 | 현재 iOS 기본 JSONEncoder는 Date를 숫자로 인코딩. 기존 응답 디코더는 시간대 없는 문자열 기준 | 일반 API는 +09:00 문자열, 운동 원본은 Apple epoch 유지. 두 인코딩을 분리하고 디코더는 소수 초/오프셋 포함 문자열 지원 |
| 2 | 중복 전송·재실행 | 현재 명세는 Idempotency-Key와 쿼터별 원본 유일성 사용 | 고정 업로드 식별자, 원본, 쿼터 매핑과 미전송 상태를 앱 재실행 후에도 유지. 서버 저장 성공 후 전송 완료 처리 |
| 2 | 워치 기록 삭제 시점 | 확인한 코드는 Watch → iPhone 파일 전송 완료 시 워치 로컬 쿼터 기록 삭제 | iPhone이 파일과 개인 기록을 먼저 영속 저장했는지 확인. 서버 업로드 실패 시 폰에서 복구 가능하게 하기 |
| 2 | 중단·재측정 | 현재 DB는 쿼터당 원본 파일 한 건 | 하나로 병합할지, 재측정을 금지/교체할지, 여러 파일을 저장할지. 여러 파일 저장은 스키마 변경 필요 |
| 2 | 서버 마감과 업로드 순서 | WORK-01은 서버 endedAt이 있어야 수신 | 마감 성공 후 업로드할지, 폰이 파일을 보관하며 기다릴지. 선업로드 수신 허용은 별도 계약 변경 |
| 2 | 업로드의 If-Match | 현재 초안은 부모 경기 최신 버전 필수 | 지연 업로드가 다른 쿼터 변경과 충돌할 수 있으므로 소유권·쿼터 ID·중복 검증으로 분리하는 개선안 검토. 아직 현 계약에서 제거하지 않음 |
| 2 | 센서 샘플 시간 경계 | 현재 초안은 모든 샘플이 startDate~endDate 안에 있어야 함 | 비동기 센서 경계값은 원본 보존 후 계산 대상에서 제외할지, 허용 오차를 둘지 합의. 현재 검증 규칙은 상세 문서 유지 |
| 2 | 최대심박수 출처 | WORK-06으로 개인 기준 최대심박수 설정 가능 | 사용자 입력/건강 데이터 등 출처와 UI 결정. 없으면 TRIMP=null, 쿼터 관측 최고심박수를 자동 대입하지 않기 |
| 3 | 결과 대기·누락 표시 | 요약은 null 또는 PROCESSING/PARTIAL/READY/FAILED | 화면 문구와 조회 중단·재시도 조건. null을 0으로 표시하지 않기 |
| 3 | 위치·심박 원본 조회 | 원본 페이지 기본 limit=20, 상한100은 기술 초안 | 그래프/히트맵에 필요한 개수, 여러 페이지 병합, 업로드 크기·타임아웃·재시도 한도 |
| 3 | 오프라인 조작 명령 큐 | WATCH-01/02는 #44에서 보류, 현재 미제공 | 확정(#44): 상태 변경은 온라인 일반 API만 사용한다. 응답 유실은 동일 멱등 요청 재전송으로 복구 |

## 3. 서버 계산 기준으로 별도 확정할 내용

| 지표 | 결정할 내용 | iOS 영향 |
| --- | --- | --- |
| 평균속력 | 휴식·일시정지 시간을 포함할지 | 화면의 운동 시간과 평균속력 설명을 일치시킴. 현재 DTO에는 pause 구간 없음 |
| 고강도 거리 | 심박 임계값과 주행 최소 속도 | 단위 m로 표시. 기준 설명 필요 |
| 가속·감속 횟수 | 가속도 임계값·최소 지속·재진입·누락 처리 | 이벤트 횟수로 표시 |
| 방향전환 횟수 | 회전각·최소 속도·중복 방지 | GPS 이동 방향 기반 지표임을 이해 |
| 심박·Edwards | 유효 심박 구간, 보간, HRmax 범위 초과 처리 | null 사유와 기준값 입력 안내 |

원본으로 같은 지표를 iOS에서도 계산한다면 서버와 산식·필터·단위를 통일해야 한다. 서버 결과만 표시한다면 iOS가 산식을 중복 구현할 필요는 없다. 임계값은 이 문서에서 임의 숫자로 확정하지 않는다.
