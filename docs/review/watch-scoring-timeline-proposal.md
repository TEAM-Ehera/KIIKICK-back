# 워치 득점·어시스트 타임라인 연동 초안

관련 이슈 #87. 이 문서는 구현 전 iOS·watchOS와 검토할 제안이다.

## 데이터 흐름

1. 워치는 플레이 중 득점 또는 어시스트 버튼을 누른 순간의 시각과 해당 위치를 쿼터별 이벤트로 기록한다. 경기 종료 후 쿼터 운동 원본, 이벤트, 경기 식별 정보를 iPhone으로 넘긴다.
2. iPhone은 워치 GPS 원본을 경기 ID와 쿼터 ID로 로컬에 보관하고, 완료 경기의 모든 쿼터 운동 원본과 이벤트를 서버에 제출한다. 앱 재시작이나 응답 유실 뒤에도 같은 업로드를 재시도할 수 있도록 요청 정보를 유지한다.
3. 서버는 운동 원본과 이벤트를 함께 저장하고 기존 비동기 계산으로 운동 요약을 만든다. iPhone은 결과의 분석 상태와 요약을 조회한 뒤, 이벤트의 시각과 좌표를 로컬 GPS 경로에 표시한다.

## 제출과 저장 제안

기존 `POST /api/v1/matches/{matchId}/workout-submissions` 요청의 쿼터 항목에 `scoringEvents`를 추가한다. 각 이벤트는 워치가 생성한 고정 `eventId`, `type` (`GOAL` 또는 `ASSIST`), `timestamp`, `latitude`, `longitude`를 갖는다. 요청의 시각은 운동 샘플과 같은 Apple epoch 초를 사용하고, 응답에서는 기존 결과 API의 ISO 8601 형식을 따른다.

- 이벤트 시간은 해당 쿼터 운동 구간 안에 있어야 한다. 좌표가 있으면 위도와 경도를 함께 저장하고 범위를 검증한다. 체크 당시 좌표를 확보하지 못했다면 두 값 모두 비워 두고 유형과 시각을 보존하는 방안을 제안한다.
- 이벤트 배열이 제공된 쿼터는 그 배열을 최종본으로 보고 유형별 합계를 계산한다. 빈 배열은 0건으로 처리한다. 필드를 생략한 기존 앱 제출은 기존 합계를 보존한다.
- 인증된 경기 소유자와 제출된 쿼터의 소속을 확인한다. 기존 `Idempotency-Key`, `If-Match` 계약을 재사용한다. 동일 제출의 재시도는 이벤트와 합계를 중복 저장하지 않으며, 실패하면 해당 경기 제출의 변경을 함께 되돌린다.

## 결과와 GPS 원본

- 경기 결과는 기존 `summaryAvailability`로 비동기 분석 진행 상태를 알려준다. 쿼터별 결과는 기존 요약과 함께 이벤트 타임라인을 시각 순서로 제공한다. iPhone은 쿼터별 목록으로 경기 전체 타임라인을 구성할 수 있다.
- GPS 샘플 원본은 서버에 보존하고 기존 운동 분석에 사용한다. 제출 응답과 결과 응답은 이벤트 한 건의 좌표와 이동 경로 샘플 배열을 구분한다. 전체 경로 렌더링은 iPhone의 로컬 GPS 샘플을 사용한다.
- 기존 `GET /api/v1/quarters/{quarterId}/track-points`를 사용하는 앱의 전환 여부를 확인한 뒤, 경로 원본 조회 API를 단계적으로 종료하는 일정을 정한다.

## 구현 전 합의할 항목

- 워치가 이벤트와 함께 보낼 수 있는 좌표의 가용성과 정확도, GPS 미수신 시 iOS 표시 방식
- 종료 후 잘못 기록된 이벤트 정정 지원 여부와 기존 수동 합계가 있을 때의 적용 순서
- 기존 iOS 버전의 GPS 원본 조회 사용 여부와 로컬 GPS가 없는 과거 경기의 표시 방식
